# Role 4 – Shipping API Specification

## Overview

The Shipping API is an ASP.NET Web API 2 service used by the eStoreJA website after a payment has been approved. It stores shipment records in the `eStoreJA_DB` SQL Server database and returns tracking information to the website.

Base URL (local IIS Express): `https://localhost:44355/`

All request and response bodies use JSON.

## 1. Create shipment

**Endpoint:** `POST /api/shipments`

**Purpose:** Creates a shipment for a paid order and returns a unique tracking number. The operation is idempotent by `OrderId`: if the same order is submitted again (for example, after a temporary network failure), the API returns the existing tracking number instead of creating a duplicate shipment.

### Request

```json
{
  "OrderId": 1001,
  "CustomerName": "Jane Brown",
  "ProductName": "Bluetooth Headphones ×1, Coffee ×2",
  "Quantity": 3,
  "AddressLine1": "10 Example Street",
  "AddressLine2": "",
  "City": "Kingston",
  "State": "Kingston",
  "Country": "Jamaica",
  "ZipCode": "00000"
}
```

`OrderId`, `CustomerName`, `ProductName`, `Quantity`, `AddressLine1`, `City`, `State`, `Country` and `ZipCode` are required. `AddressLine2` is optional. Quantity must be greater than zero.

### Successful response – HTTP 200

```json
{
  "TrackingNumber": "ESTJ261123A1B2C3D4"
}
```

The tracking number is generated by the service and stored with the shipment. New shipments begin with status `Processing`; the estimated delivery date is set to five days after creation.

### Validation response – HTTP 400

Returned when the body is missing or required values are invalid.

### Server response – HTTP 500

Returned when the database operation fails. Check the Shipping API connection string and confirm that `Database/AddShipments.sql` has been executed.

## 2. Track shipment

**Endpoint:** `GET /api/shipments/{trackingNumber}`

**Purpose:** Finds a shipment by its tracking number and returns the current status and delivery dates.

### Successful response – HTTP 200

```json
{
  "TrackingNumber": "ESTJ261123A1B2C3D4",
  "Status": "In Transit",
  "EstimatedDelivery": "2026-11-28T12:00:00",
  "ActualDelivery": null
}
```

Possible statuses: `Processing`, `Shipped`, `In Transit`, `Out for Delivery`, `Delivered`.

`ActualDelivery` remains `null` until the shipment is marked as delivered.

### Not found – HTTP 404

Returned when no shipment has the supplied tracking number.

### Server response – HTTP 500

Returned when the service cannot read shipment data from SQL Server.

## 3. Database and application integration

- `POST /api/shipments` is called after the payment service approves a payment and the order is saved.
- The eStoreJA website stores the returned tracking number in `Orders.TrackingNumber`.
- `GET /api/shipments/{trackingNumber}` is called by the Track Package page.
- The Order History page displays only orders belonging to the currently authenticated user.
- A shipment is unique per order (`Shipments.OrderId` has a unique constraint).

## 4. Security and assumptions

- Customer pages require the existing authenticated session (`SecurePage`).
- Order history filters by the logged-in user's ID; it does not accept a user ID from the browser.
- The local API URL uses HTTPS through IIS Express.
- This coursework implementation simulates shipment status updates. It does not connect to a live DHL carrier tracking service.
- The API connection string must point to the same SQL Server database used by eStoreJA.
